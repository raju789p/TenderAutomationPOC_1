# Content placement instructions for the conversion planner

Place each source element in exactly one target section. Keep source heading hierarchy. Use these target sections:

- `abstract`: purpose and a brief summary of the methodology.
- `scope`: boundaries, applicability, roles, and what the method covers.
- `introduction`: context, background, and framing for the method.
- `learning_objectives`: skills or outcomes a learner should achieve.
- `core_concept`: foundational principles, terminology, and central ideas.
- `process_detail`: phases, steps, workflow, controls, and implementation detail.
- `when_to_use`: conditions, fit, selection criteria, or situations where the method applies.
- `best_practices`: recommended ways to apply or maintain the method.
- `advantages`: strengths and benefits.
- `limitations`: risks, weaknesses, constraints, and drawbacks.
- `unclassified`: use when no section is a clear fit.

Every element id must occur exactly once. Do not drop or invent ids. Do not merge elements, reorder elements within a target section, or reword any source text. Keep headings in their original hierarchy. Tables and images must remain their own block types. If unsure, use `unclassified`.

Printed page-number elements are still included once in the plan as `paragraph` references; the renderer regenerates page numbering and records those source elements as regenerated. A contents table is likewise referenced once and regenerated by the renderer.

Fonts, paragraph styles, and visual formatting are not planning decisions. Code applies them from `config/target_format.yaml`.
